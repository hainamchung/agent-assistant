## Architecture Paradigm

Agent Assistant is a **document-driven multi-agent orchestration framework**. It does not follow traditional client-server, microservices, or monolithic patterns. Instead:

- **Markdown is the bytecode**: Agent definitions, commands, rules, and skills are Markdown/YAML files that the AI model executes by loading them into its context window
- **The AI model is the runtime**: There is no separate application server. The coding assistant (Claude, Copilot, Cursor, etc.) is both the execution engine and the interface
- **Files are the API**: Agent handoffs, skill resolution, and workflow routing are declared in file frontmatter and resolved by the orchestration protocol
- **Global install, local execution**: The framework installs once to `~/.<platform>/` and applies to every project opened in that AI tool

## Layer Descriptions

### Layer 1: User Interface
The user interacts via their AI coding tool's chat interface. Input is either natural language or explicit `/command` syntax.

### Layer 2: AI Model Runtime
The AI model (Claude, Copilot, etc.) loads the platform entry file (e.g., `COPILOT.md`), which triggers the boot sequence for the orchestrator.

### Layer 3: Orchestrator (RUNTIME.md)
The core protocol that governs all behavior. Defines identity, laws, command routing, phase execution, agent delegation, evaluation, and error handling. Loaded in tiers (NANO/MICRO/FULL) based on task complexity.

### Layer 4: Command Router
Routes user requests to the appropriate workflow. Each command has a router file and variant subdirectory. The router detects the variant (`:fast`, `:hard`, `:team`) and loads the corresponding workflow definition.

### Layer 5: Skill Resolver (HSOL)
The Hybrid Skill Orchestration Layer resolves domain skills based on agent profile + project context. Skills provide domain expertise without manual wiring.

### Layer 6: Agent Pool
21 specialist agents with declared roles, handoffs, guardrails, and evaluation criteria. Agents are instantiated by the orchestrator through EMBODY (shared context) or SUB-AGENT (isolated context) execution.

### Layer 7: Execution Topologies
12 coordination patterns that define how multiple agents interact: pipeline, fan-out, golden-triangle, swarm, etc.

### Layer 8: Guardrails
7 safety constraint modules that constrain agent behavior. Applied via frontmatter declarations. Include injection defense, output sanitization, privacy, and escalation protocols.

### Layer 9: File System
The physical Markdown/YAML/JSON files installed in the user's home directory under the platform-specific path.

## Interaction Model

1. **User → Orchestrator**: Natural language or `/command` input
2. **Orchestrator → Command Router**: Determines command and variant
3. **Command Router → Workflow**: Loads phase definitions
4. **Workflow → Agent Pool**: Delegates each phase to specialist agent(s)
5. **Agent → Skill Resolver**: Requests domain skills based on profile
6. **Agent → Guardrails**: Constraints applied during execution
7. **Agent → Topology**: Multi-agent coordination pattern activated
8. **Agent → Agent**: Handoffs via declared `handoffs:` field
9. **Agent → Orchestrator**: Phase deliverable returned
10. **Orchestrator → User**: Synthesized result delivered

## Component: Orchestrator

| Property | Value |
|----------|-------|
| **Source** | `rules/RUNTIME.md` (+ 40 supporting rule files) |
| **Type** | Protocol (document-driven) |
| **Responsibility** | Identity enforcement, command routing, phase execution, agent delegation, evaluation |

**Interface**:
- **Input**: User natural language or `/command` input
- **Output**: Synthesized deliverable (code, docs, plan, review)
- **Delegates to**: Command Router, Agent Pool, Topology Engine, Evaluation Engine

**Key Behaviors**:
- Maintains the Orchestrator identity — never implements directly
- Routes commands via explicit prefix or natural language mapping
- Loads RUNTIME.md in tiers (NANO/MICRO/FULL) to optimize context
- Enforces phase ordering — cannot skip phases
- Delegates to agents via EMBODY or SUB-AGENT mode based on agent category

**Dependencies**: All other components depend on the Orchestrator; it depends on none.

## Component: Command Router

| Property | Value |
|----------|-------|
| **Source** | `commands/*.md` (17 routers) + `commands/*/` (variant dirs) |
| **Type** | Workflow definitions (Markdown) |
| **Responsibility** | Map user intent to workflow phases and agent assignments |

**Interface**:
- **Input**: Command name + variant (e.g., `/cook:fast`)
- **Output**: Ordered phase list with agent assignments and exit criteria

**Routing Logic**:
1. Router file (`commands/{cmd}.md`) determines variant from suffix or defaults
2. Variant file (`commands/{cmd}/{variant}.md`) defines the full workflow
3. Each workflow specifies: phases, agent per phase, topology, exit criteria, deliverables

**Execution Modes**:
| Mode | Files | Agents | Quality |
|------|-------|--------|---------|
| `:fast` | `{cmd}/fast.md` | 1-2 agents | Speed-optimized |
| `:hard` | `{cmd}/hard.md` | 3-5 agents | Full analysis (default) |
| `:team` | `{cmd}/team.md` | 3 agents (Golden Triangle) | Adversarial collaboration |

## Component: Skill Resolver (HSOL)

| Property | Value |
|----------|-------|
| **Source** | `matrix-skills/*.yaml` (23 files) + `skills/*/SKILL.md` (1400+) |
| **Type** | Resolution engine (document-driven) |
| **Responsibility** | Match agent profiles to relevant domain skills |

**Interface**:
- **Input**: Agent `profile` field (e.g., `backend:execution`) + project context signals
- **Output**: Resolved skill set injected into agent context

**Resolution Hierarchy**:
1. **Matrix Skills** (`matrix-skills/`): Pre-defined profile→skill mappings in YAML
2. **Library Skills** (`skills/`): Deep skill directories with `SKILL.md` definitions
3. **Dynamic Skills** (`_dynamic.yaml`): Community-installable extensions

**Matching Criteria**: Agent profile domain + category → domain registry → matching skills.

## Component: Evaluation Engine

| Property | Value |
|----------|-------|
| **Source** | `rules/EVALUATION.md` |
| **Type** | Quality scoring protocol |
| **Responsibility** | Score agent output on 5 dimensions |

**Dimensions**:
| Dimension | Weight | Description |
|-----------|--------|-------------|
| D1: Correctness | 30% | Functional accuracy |
| D2: Completeness | 25% | Coverage of requirements |
| D3: Style | 15% | Code quality and conventions |
| D4: Security | 20% | OWASP compliance, vulnerability check |
| D5: Performance | 10% | Efficiency and resource usage |

**D4 Override**: Security failures override all other dimensions — a critical security issue fails the evaluation regardless of other scores.

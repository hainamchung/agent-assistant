## Entity: Agent

**Definition**: A specialist agent with a distinct role, expertise area, behavioral constraints, and collaboration protocols.

**Attributes**:

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `schema-version` | string | Yes | Schema version (currently "1.0") |
| `name` | string | Yes | Unique agent identifier |
| `description` | string | Yes | One-line role description |
| `profile` | string | Yes | `{domain}:{category}` for HSOL matching |
| `skill-profile` | string | Yes | Primary skill keyword |
| `handoffs` | string[] | Yes | Agents this agent can delegate to |
| `version` | string | Yes | Agent definition version |
| `category` | enum | Yes | execution/meta/investigation/validation/research/support |
| `role-scope` | enum | Yes | implementation/coordination/analysis/review/research/support |
| `personality` | object | Yes | tone, verbosity, style, humor |
| `capabilities` | string[] | Yes | Capability keywords |
| `scope.files` | string[] | Yes | Glob patterns for file access |
| `scope.tasks` | string[] | Yes | Allowed task types |
| `scope.restrictions` | string[] | Yes | Forbidden actions |
| `guardrails` | string[] | Yes | Applied guardrail modules |
| `voice` | object | Yes | adaptation, deviation_tolerance |
| `preflight` | string[] | Yes | Pre-execution validation checks |

**Relationships**:
- **handoffs** → other Agents (directed, named)
- **guardrails** → Guardrail entities (references by name)
- **profile** → Skills (matched by HSOL resolution)
- **belongs to** → Team (optional, via team assignments)

**Lifecycle**: Static — defined once, updated via PR, validated by `lint-agents.js`, never created at runtime.

## Entity: Command

**Definition**: A user-facing workflow entry point that routes to variant workflow definitions.

**Attributes**:

| Attribute | Type | Description |
|-----------|------|-------------|
| Name | string | Command identifier (e.g., `cook`, `fix`, `test`) |
| Router | Markdown file | `commands/{cmd}.md` — variant detection logic |
| Variants | directory | `commands/{cmd}/` — variant workflow files |
| Modes | enum set | `:fast`, `:hard` (default), `:team` |
| Phases | ordered list | Agent assignments per phase |
| Topology | reference | Coordination pattern to use |
| Exit Criteria | checklist | Phase completion requirements |
| Deliverables | list | Expected output artifacts |

**Relationships**:
- **routes to** → Workflow variants (files)
- **assigns** → Agents (per phase)
- **uses** → Topology (coordination pattern)

## Entity: Topology

**Definition**: An execution coordination pattern that defines how multiple agents interact during a workflow.

**Attributes**:

| Attribute | Type | Description |
|-----------|------|-------------|
| Name | string | Topology identifier (e.g., `pipeline`, `fan-out`) |
| Pattern | enum | Sequential, parallel, adversarial, etc. |
| Roles | list | Agent role slots |
| Ordering | specification | Phase ordering rules |
| Synthesis | specification | How to merge parallel outputs |
| Exit Criteria | checklist | Topology completion requirements |

**Relationships**:
- **orchestrates** → Agents (role assignments)
- **referenced by** → Commands (workflow definitions)

## Entity: Skill

**Definition**: A domain expertise unit that provides specialized knowledge to agents.

**Two forms**:
1. **Matrix Skill**: Entry in `matrix-skills/{domain}.yaml` — lightweight, profile→skill mapping
2. **Library Skill**: Directory in `skills/{name}/SKILL.md` — deep skill definition with protocol

**Matrix Skill Attributes**:

| Attribute | Type | Description |
|-----------|------|-------------|
| Name | string | Skill identifier |
| Domain | string | Parent domain (e.g., backend, security) |
| Profile match | string | Agent profile pattern for resolution |

**Relationships**:
- **resolved by** → HSOL (based on agent profile + project context)
- **applied to** → Agent (during execution)

## Entity: Guardrail

**Definition**: A behavioral constraint module that restricts agent actions for safety.

**Attributes**:

| Attribute | Type | Description |
|-----------|------|-------------|
| Name | string | Guardrail identifier |
| Scope | string | What it constrains (input, output, privacy, etc.) |
| Rules | list | Specific constraint rules |
| Escalation | protocol | What happens on violation |

**Relationships**:
- **applied to** → Agent (via `guardrails:` frontmatter field)
- **part of** → I/O Pipeline (ordered stages)

---

## Entity: Rule

**Definition**: A protocol document that defines behavioral constraints for the orchestration system.

**Categories**:
- Core protocol (`RUNTIME.md`)
- Supporting protocols (EVALUATION, TEAMS-LITE, SKILLS-LITE, etc.)
- Intelligence protocols (DURABLE-EXECUTION, CONTEXT-DECAY, etc.)
- Security protocols (SKILL-SECURITY, etc.)

**Relationships**:
- **governs** → Orchestrator, Agents, Commands
- **references** → other Rules (loading chains)

---

## Entity: Team

**Definition**: A Golden Triangle team composed of Tech Lead + Executor + Reviewer for adversarial collaboration.

**Attributes**:

| Attribute | Type | Description |
|-----------|------|-------------|
| Name | string | Team domain (e.g., `backend-team`) |
| Tech Lead | agent reference | Coordination agent |
| Executor | agent reference | Implementation agent |
| Reviewer | agent reference | Adversarial review agent |
| Domain | string | Specialization area |

**Relationships**:
- **composed of** → 3 Agents (Tech Lead, Executor, Reviewer)
- **activated by** → `:team` command variants

---

## Entity: Persona

**Definition**: A communication style profile that controls agent tone, formality, and expression.

**Variants**: professional, casual, mentor, academic

**Relationships**:
- **applied to** → Agent (via voice coherence protocol)

## Entity: Platform

**Definition**: A supported AI coding tool with specific capabilities and configuration.

**Attributes**:

| Attribute | Type | Description |
|-----------|------|-------------|
| Name | string | Platform identifier |
| Tool path | string | Home directory path (e.g., `.copilot`) |
| Boot file | string | Entry file name |
| Capabilities | object | Boolean flags (sub-agents, terminal, MCP, etc.) |
| Max context | number | Token limit |
| Adapter hints | object | Default tier, execution model |

**Relationships**:
- **hosts** → all other entities (installed to platform path)
- **configured by** → `platforms.json`

## Contract Model

Agent Assistant has no HTTP API server. Contracts are **document-based interfaces** — structured formats that components agree to follow. Enforcement is via:

1. **Schema validation** (`lint-agents.js`) — validates agent frontmatter at CI time
2. **Static simulation** (`simulate.js`) — validates handoff integrity and skill references
3. **Output validation** (`validate-output.js`) — validates deliverable schemas
4. **Convention** — Markdown structure patterns followed by all components

## Contract: Agent Frontmatter

**Parties**: Agent authors ↔ Orchestrator ↔ Scripts

**Format**: YAML frontmatter delimited by `---` in `.md` files

**Required Fields** (schema v1.0):
- `schema-version`, `name`, `description`, `profile`, `skill-profile`
- `handoffs`, `version`, `category`, `role-scope`
- `personality` (tone, verbosity, style, humor)
- `capabilities`, `scope` (files, tasks, restrictions)
- `guardrails`, `voice`, `preflight`

**Validation**: `scripts/lint-agents.js` enforces rules R001–R302 in CI.

**Breaking Change Policy**: Schema version bump required for new required fields.

## Contract: Command Workflow Structure

**Parties**: Command authors ↔ Orchestrator

**Structure** (expected in variant files):

```markdown
# Command: {name} ({variant})

## Phases

### Phase 1: {Name}
- **Agent**: {agent-name}
- **Mode**: EMBODY | SUB-AGENT
- **Input**: {what the agent receives}
- **Output**: {expected deliverable}
- **Exit Criteria**: {checklist}

### Phase 2: {Name}
...
```

**Conventions**:
- Phases are numbered and sequential
- Each phase names exactly one primary agent
- Exit criteria are explicit and checkable
- Deliverables are typed (code, document, review, plan)

## Contract: Handoff Protocol

**Parties**: Agent ↔ Agent (via Orchestrator mediation)

**Declaration** (in agent frontmatter):
```yaml
handoffs: [tester, database-architect, security-engineer]
```

**Rules**:
- An agent can only hand off to agents declared in its `handoffs` list
- Handoff targets must be valid agent names (validated by `lint-agents.js`)
- The Orchestrator mediates all handoffs — agents never communicate directly
- Handoff includes: task context, deliverables from current phase, constraints

**Validation**: `scripts/simulate.js` checks all handoff targets exist and are bidirectionally reachable.

## Contract: Skill Resolution Interface

**Parties**: HSOL ↔ Agent ↔ Skill Registries

**Resolution Input**:
```
Agent profile: "backend:execution"
Agent skill-profile: "REST API"
Project context: {detected frameworks, file patterns}
```

**Resolution Output**:
```
Resolved skills: [skill_1, skill_2, ...]
Source: matrix | library | dynamic
```

**Priority Order**:
1. Matrix skills matching profile domain
2. Library skills matching skill-profile keyword
3. Dynamic skills from `_dynamic.yaml`

## Contract: Guardrail Application

**Parties**: Agent ↔ Guardrail modules

**Declaration** (in agent frontmatter):
```yaml
guardrails:
  - injection-defense
  - output-sanitization
  - io-pipeline
```

**Application**:
- Each listed guardrail's rules are loaded and applied during agent execution
- The I/O pipeline (`io-pipeline.md`) defines the 4-stage processing order
- Violations trigger the escalation protocol (`violation-escalation.md`)

**Contract**: Guardrail names must match files in `guardrails/` directory.

## Contract: Evaluation Interface

**Parties**: Orchestrator ↔ Reviewer agent ↔ EVALUATION.md

**Input**: Agent deliverable (code, document, plan)

**Output**: 5-dimension score:

| Dimension | Weight | Scale |
|-----------|--------|-------|
| D1: Correctness | 30% | 0-10 |
| D2: Completeness | 25% | 0-10 |
| D3: Style | 15% | 0-10 |
| D4: Security | 20% | pass/fail (override) |
| D5: Performance | 10% | 0-10 |

**D4 Override Rule**: If D4 = fail, entire evaluation = fail regardless of other scores.

**Threshold**: Weighted score must meet minimum threshold for acceptance (defined per workflow).

## Contract: CLI Commands

**Parties**: End user ↔ CLI application

**Interface**:

| Command | Arguments | Output |
|---------|-----------|--------|
| `agent-assistant install <platform>` | Platform name or `--all` | Files synced to `~/.<platform>/` |
| `agent-assistant uninstall <platform>` | Platform name or `--all` | Files removed |
| `agent-assistant list` | None | Installed platforms with status |
| `agent-assistant create <type> <name>` | Entity type + name | Scaffolded file from template |
| `agent-assistant --version` | None | Version number |
| `agent-assistant --help` | None | Usage information |

**Exit codes**: 0 = success, 1 = error

## Contract: MCP Server

**Parties**: External AI tools ↔ MCP server (`scripts/mcp-server.js`)

**Protocol**: Model Context Protocol (MCP) — JSON-RPC over stdio

**Purpose**: Allows external integrations to query framework metadata, agent definitions, and skill registries.

**Status**: Supplementary integration — not the primary interface.

---

## Contract: Platform Entry File

**Parties**: Template generator ↔ AI coding tool

**Template**: `AGENT.template.md` with placeholders:
- `{{CAPABILITIES_BLOCK}}` — Platform capability declaration
- `{{OVERRIDES_BLOCK}}` — Platform-specific overrides

**Generation**: `scripts/generate-entry-points.js` reads `platforms.json` and produces entry files.

**Drift Detection**: `scripts/lint-entry-points.js` compares generated vs committed files in CI.

**Contract**: The generated entry file must trigger the RUNTIME.md boot sequence when the AI tool loads it.

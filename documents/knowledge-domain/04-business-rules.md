## Orchestrator Laws

Absolute rules from RUNTIME.md that cannot be overridden:

| # | Law | Description |
|---|-----|-------------|
| 1 | **Never Implement** | Orchestrator delegates, never writes code/tests/designs directly |
| 2 | **Phase Ordering** | Phases must execute in declared order — no skipping |
| 3 | **Agent Delegation** | Every implementation action must go through a specialist agent |
| 4 | **Exit Criteria** | Each phase must verify exit criteria before proceeding |
| 5 | **Language Compliance** | Respond in user's language; code/comments always in English |
| 6 | **Error Notification** | Never stop silently on error — notify user with options |

## Agent Constraints

Per-agent behavioral constraints declared in frontmatter and body:

| Constraint Type | Field | Example |
|----------------|-------|---------|
| **File scope** | `scope.files` | `["src/**", "lib/**"]` — only these files |
| **Task scope** | `scope.tasks` | `[implementation, debugging]` — only these tasks |
| **Restrictions** | `scope.restrictions` | `[no-frontend-changes]` — forbidden actions |
| **Guardrails** | `guardrails` | `[injection-defense]` — safety modules applied |
| **Confidence threshold** | Body attribute | `85% (escalate if below)` — when to ask for help |
| **Preflight checks** | `preflight` | Must pass before agent can execute |
| **Handoff boundaries** | `handoffs` | Can only delegate to listed agents |

**Invariant**: An agent cannot operate outside its declared scope. The orchestrator enforces scope boundaries.

- R001: `schema-version` must be present
- R002: `name` must be present and match filename
- R003: `description` must be present
- R004: `profile` must be present and match `{domain}:{category}` format
- R005: `handoffs` must be a non-empty array
- ... (all required fields validated)

### R100–R199: Type Validation Rules
- R100: `category` must be one of: execution, meta, investigation, validation, research, support
- R101: `role-scope` must be one of: implementation, coordination, analysis, review, research, support
- R102: `personality.tone` must be one of: technical, friendly, neutral, academic
- R103: `capabilities` must be an array of strings
- ... (all enum and type constraints)

### R200–R299: Cross-Reference Rules
- R200: All `handoffs` targets must reference existing agent files
- R201: All `guardrails` entries must reference existing guardrail files
- R202: `profile` domain must match a registered skill domain
- ... (referential integrity)

### R300–R302: Security Rules
- R300: `role-scope` must be consistent with `category` (e.g., validation→review)
- R301: Trust manifest integrity (SHA-256 hash verification)
- R302: Quarantine detection for untrusted community extensions

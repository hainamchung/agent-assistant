## Application Entry Points

### CLI Entry Point: `cli/install.js`

The primary application entry point. Declared in `package.json` as both `"main"` and `"bin"`:

```json
{
  "main": "cli/install.js",
  "bin": {
    "agent-assistant": "./cli/install.js"
  }
}
```

When invoked as `agent-assistant <command> [tool]`, this file:

1. Parses CLI arguments (install, uninstall, list)
2. Routes to platform-specific installers (`cli/lib/platforms/`)
3. Copies framework files to the AI tool's home directory (e.g., `~/.cursor/`, `~/.copilot/`, `~/.claude/`)
4. Provides interactive tool selection, progress bars, and verification

### Scaffolding Entry Point: `cli/create.js`

Secondary CLI entry point for creating new agents, commands, and topologies from templates. Invoked via:

```bash
npm run create:agent
npm run create:command
npm run create:topology
```

Reads templates from `AGENT-TEMPLATE.md` or `COMMAND-TEMPLATE.md`, substitutes placeholders, and writes to the appropriate directory.

### MCP Server Entry Point: `scripts/mcp-server.js`

Model Context Protocol server for external tool integration. Invoked via `npm run mcp:start`.

## Boot Sequence

Agent Assistant does not have a traditional application boot sequence. Instead, the "boot" happens when an AI coding tool (Cursor, Copilot, Claude Code, etc.) loads its platform entry file:

```
1. AI tool starts a session
2. AI tool reads its entry file (e.g., ~/.copilot/skills/agent-assistant/COPILOT.md)
3. Entry file instructs: "Read RUNTIME.md"
4. RUNTIME.md loading protocol determines tier (NANO / MICRO / FULL)
5. User issues a command (e.g., /cook:fast)
6. Orchestrator routes to command file (commands/cook/fast.md)
7. Command file defines phases → agents are loaded per-phase
8. Agents execute phases sequentially
```

This is a **document-driven boot** — no compiled code runs. The AI model itself is the runtime.

## Build and Script Entry Points

All scripts are run via `npm run <script>`. Key entry points:

| Script | File | Purpose |
|--------|------|---------|
| `install:cursor` | `cli/install.js install cursor` | Install for Cursor |
| `install:copilot` | `cli/install.js install copilot` | Install for GitHub Copilot |
| `install:claude` | `cli/install.js install claude` | Install for Claude Code |
| `install:all` | `cli/install.js install --all` | Install for all platforms |
| `test` | `node --test cli/*.test.js scripts/*.test.js` | Run all tests |
| `lint:agents` | `scripts/lint-agents.js` | Validate agent/command schemas |
| `simulate` | `scripts/simulate.js` | Static agent simulation |
| `wordcount` | `wc -w rules/RUNTIME.md` | Enforce ≤3200 word budget |
| `validate:schemas` | `scripts/lint-rules/deliverable-schemas.js` | Schema validation |
| `validate:a2a` | `scripts/generate-a2a-cards.js --validate` | A2A card validation |
| `ci:local` | Combined lint+simulate+validate | Full local CI check |
| `generate:entry-points` | `scripts/generate-entry-points.js` | Generate platform entry files |
| `generate:tiers` | `scripts/split-runtime-tiers.js` | Split RUNTIME.md into tier files |
| `mcp:start` | `scripts/mcp-server.js` | Start MCP server |
| `trust:hashes` | `scripts/generate-trust-hashes.js` | Generate SHA-256 trust hashes |
| `trust:verify` | `scripts/generate-trust-hashes.js --verify` | Verify trust hashes |

### pre-commit Hook Chain

The `pre-commit` hook runs `npm run ci:local`, which chains:

```
lint:agents → lint:drift → simulate → wordcount → validate:schemas → validate:a2a → trust:verify
```

## Platform Entry Points

Each supported AI tool has a Markdown entry file at the project root:

| File | Platform | Installed To |
|------|----------|-------------|
| `CLAUDE.md` | Claude Code | `~/.claude/CLAUDE.md` |
| `COPILOT.md` | GitHub Copilot | `~/.copilot/COPILOT.md` |
| `CURSOR.md` | Cursor | `~/.cursor/rules/CURSOR.md` |
| `CODEX.md` | Codex | `~/.codex/CODEX.md` |
| `GEMINI.md` | Gemini (Antigravity) | `~/.antigravity/GEMINI.md` |
| `QWEN.md` | Qwen | `~/.qwen/QWEN.md` |

All entry files follow the same pattern:
1. Declare platform identity
2. Instruct the AI to read `rules/RUNTIME.md`
3. Apply the LOADING PROTOCOL for tier-aware loading
4. Activate orchestrator mode

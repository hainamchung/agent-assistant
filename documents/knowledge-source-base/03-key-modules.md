## Module: `cli/`

**Purpose**: CLI tooling for global installation, uninstallation, and scaffolding of the framework.

**Internal Structure**:

| File | Purpose | Exports/Behavior |
|------|---------|-----------------|
| `install.js` | Main CLI entry — routes install/uninstall/list commands | Executable (bin entry) |
| `create.js` | Scaffolds new agents, commands, topologies from templates | Executable (npm script) |
| `install.test.js` | Test suite for the installer | Node.js test runner |
| `lib/config.js` | TOOLS configuration, paths, file lists | `TOOLS`, platform configs |
| `lib/fs-utils.js` | File system utilities (copy, sync, verify) | `copyDir`, `syncFiles` |
| `lib/progress.js` | Progress bar and formatting | `formatNumber` |
| `lib/prompts.js` | Interactive prompts for tool selection | Prompt functions |
| `lib/ui.js` | Banner, usage, and display functions | `printBanner`, `printUsage`, `listTools` |
| `lib/wizard.js` | Interactive wizard flow | Wizard functions |
| `lib/platforms/` | Per-platform install/uninstall logic for each AI tool | Platform-specific installers |

**Dependencies**: Node.js built-in modules only (`fs`, `path`, `readline`). Zero external runtime dependencies.

**Key Design Decision**: The CLI has no external dependencies to minimize install footprint and avoid supply chain risk.

## Module: `scripts/`

**Purpose**: DevOps tooling for validation, generation, benchmarking, and maintenance.

**Internal Structure**:

| File | Purpose |
|------|---------|
| `lint-agents.js` | Validates all agent and command frontmatter against schema v1.0 (rules R001-R302) |
| `simulate.js` | Static simulation: checks frontmatter, handoff integrity, required sections, skill references |
| `validate-output.js` | Validates workflow output against deliverable schemas (rules V001-V006) |
| `workflow-regression.js` | Regression testing for workflow execution patterns |
| `generate-entry-points.js` | Generates platform entry files from `AGENT.template.md` + `platforms.json` |
| `split-runtime-tiers.js` | Splits RUNTIME.md into NANO/MICRO tier files |
| `generate-a2a-cards.js` | Generates Agent-to-Agent card JSON from agent Markdown files |
| `generate-trust-hashes.js` | Generates/verifies SHA-256 integrity hashes for trust manifest |
| `generate-gallery-data.js` | Extracts agent/command metadata into web gallery JSON |
| `mcp-server.js` | MCP (Model Context Protocol) server for external integrations |
| `measure-context.js` | Measures context window usage for optimization |
| `predict-cost.js` | Token cost estimation with verbose and JSON modes |
| `extract-patterns.js` | Post-workflow pattern learning from execution data |
| `regression-detect.js` | Baseline comparison for performance regression detection |
| `checkpoint-manager.js` | CLI for listing/viewing/pruning checkpoint files |
| `rollback.js` | Git-first rollback with non-git fallback |
| `migrate-schema.js` | Schema migration (add-field, set-value operations) |
| `summarize-skills.js` | Generates skill summaries from the skills library |
| `run-benchmarks.js` | Benchmark execution runner |
| `test-agent.js` | Agent-specific testing |
| `lint-entry-points.js` | Validates entry point file drift |
| `patch-bundled-deps.js` | Patches bundled dependency issues (prepare script) |

**Sub-module: `scripts/lint-rules/`**:

| File | Purpose |
|------|---------|
| `security-checks.js` | Role-scope, trust manifest, and quarantine validation (R300-R302) |
| `locale-validation.js` | Validates locale pack schema and field types |
| `topology-validation.js` | Validates topology-overrides against actual topologies |
| `tier-validation.js` | Validates contributor manifest schema |
| `composition-validation.js` | Validates skill composition rules |
| `deliverable-schemas.js` | Validates deliverable output schemas |
| `preflight-check.js` | Validates preflight field on agents |
| `validation-checks.js` | General validation utilities |
| `yaml-lite.js` | Lightweight YAML parser (no external deps) |

**Dependencies**: Node.js built-in modules only. The `yaml-lite.js` is a custom lightweight parser to avoid external YAML library dependencies.

## Module: `agents/`

**Purpose**: 21 specialist agent definitions, each as a Markdown file with YAML frontmatter.

**Key Agents by Category**:

| Category | Agents |
|----------|--------|
| **execution** | backend-engineer, frontend-engineer, mobile-engineer, game-engineer |
| **meta** | tech-lead, project-manager |
| **investigation** | debugger, scouter, performance-engineer |
| **validation** | reviewer, tester |
| **research** | researcher, brainstormer |
| **support** | docs-manager, reporter, designer, business-analyst, database-architect, devops-engineer, security-engineer, planner |

**Sub-module: `agents/teams/`** — 17 domain-specific Golden Triangle teams (backend-team, frontend-team, fullstack-team, etc.), each containing role assignments for tech-lead, executor, and reviewer.

## Module: `commands/`

**Purpose**: 17 command routers with variant workflow files.

**Structure Pattern**: Each command has a router file (`commands/{cmd}.md`) and a subdirectory (`commands/{cmd}/`) containing variant files (`fast.md`, `hard.md`, `team.md`).

**Command Categories**:

| Category | Commands |
|----------|----------|
| Build | `/cook`, `/code`, `/fix` |
| Quality | `/test`, `/review`, `/debug` |
| Planning | `/plan`, `/brainstorm`, `/design` |
| Documentation | `/docs` (core, business, audit) |
| Delivery | `/deploy` (check, preview, production, rollback) |
| Reporting | `/report` |
| Knowledge | `/ask` |
| Automation | `/auto`, `/quick` |
| Discovery | `/help` |

## Module: `rules/`

**Purpose**: 41 protocol files defining the orchestration operating model.

**Core Files**:

| File | Purpose | Loading |
|------|---------|---------|
| `RUNTIME.md` | Single source of truth — identity, laws, routing, phases, agents | Always (tiered) |
| `REFERENCE.md` | Expanded details, lookup tables, persona overrides | On-demand |
| `EVALUATION.md` | 5-dimension evaluation scoring with D4 security | On-demand |
| `TEAMS-LITE.md` | Team assembly rules and signal keywords | On-demand (:team) |
| `SKILLS-LITE.md` | Skill resolution protocol | On-demand |
| `ERRORS.md` | Error handling and recovery | On-demand |

**Supporting Protocol Files**: DURABLE-EXECUTION, CONTEXT-DECAY, VOICE-COHERENCE, VALIDATION-GATES, CONDITIONAL-HANDOFFS, AGENT-JOURNALS, SKILL-SECURITY, PROJECT-DETECTION, TOKEN-PREDICTION, ROLLBACK, HANDOFF-COMPRESSION, PATTERN-EXTRACTION, COMMUNITY-TIERS, CROSS-PROJECT, and more.

## Module: `matrix-skills/`

**Purpose**: 21 YAML domain registries + 1 index + 1 dynamic registry = 23 files total. Defines the Hybrid Skill Orchestration Layer (HSOL) that maps agent profiles to relevant skills.

**Key Files**: `_index.yaml` (central registry, 1430 matrix skills across 19 domains), `_dynamic.yaml` (community-installed), domain files: backend.yaml, frontend.yaml, security.yaml, cloud.yaml, etc.

---

## Module: `skills/`

**Purpose**: ~1400+ domain skill directories. Each contains a `SKILL.md` file defining a reusable domain skill. Skills are resolved dynamically by HSOL based on agent profile matching.

---

## Module: `topologies/`

**Purpose**: 12 execution topology templates defining how phases and agents interact.

| Topology | Pattern |
|----------|---------|
| `pipeline` | Sequential: P1→P2→P3 (default) |
| `fan-out` | Parallel dispatch, collect, synthesize |
| `hierarchical` | Lead decomposes → sub-leads → specialists |
| `golden-triangle` | Tech-lead + executor + reviewer adversarial |
| `debate-round-robin` | Adversarial reasoning rounds |
| `swarm` | Autonomous parallel execution |
| `parallel-branch` | Independent parallel branches |
| Others | review-pipeline, audit-pipeline, research-fan-out, round-robin, feature-hierarchical |

## Module: `guardrails/`

**Purpose**: 7 safety constraint modules that agents reference in their `guardrails:` frontmatter field.

| Guardrail | Purpose |
|-----------|---------|
| `injection-defense.md` | Prompt injection prevention |
| `output-sanitization.md` | Output content safety |
| `io-pipeline.md` | 4-stage I/O pipeline (validate→process→format→escalate) |
| `auth-patterns.md` | Authentication/authorization patterns |
| `data-privacy.md` | Data privacy constraints |
| `resource-limits.md` | Resource usage boundaries |
| `violation-escalation.md` | Violation handling and escalation |

---

## Module: `personas/`

**Purpose**: 4 personality profile YAML files (professional, casual, mentor, academic) with locale packs for cultural adaptation. Agents reference personas for tone, formality, and communication style.

---

## Module: `schemas/`

**Purpose**: Formal schema definitions. Contains `agent-schema.md` (canonical schema for agent frontmatter), `contract-example.yaml`, and `registry-entry.yaml`.

---

## Module: `web/`

**Purpose**: React 19 + Vite documentation website. TypeScript-based with React Router, Framer Motion, Lucide icons, and XY Flow for diagrams.

**Key Structure**: `src/pages/` (route pages including Gallery), `src/components/` (UI components), `src/data/` (generated data from scripts), `src/hooks/`, `src/styles/`.

**Testing**: Vitest with coverage support. **Deployment**: Vercel (configured via `vercel.json`).

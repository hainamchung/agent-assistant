## JavaScript Style

Based on patterns observed across `cli/` and `scripts/`:

### Module System
- **ESM**: All JavaScript files use ES Module syntax
- Import using `import` statements (not `require`)
- Package.json does not declare `"type": "module"` — scripts use `.js` extension with ESM constructs

### Coding Patterns
- Node.js built-in modules only (zero external dependencies in runtime)
- `import { readFileSync, writeFileSync } from 'fs'` — named imports
- `import path from 'path'` — default imports for built-in modules
- `process.exit(0)` / `process.exit(1)` for clear exit codes
- `console.log()` for output, `console.error()` for errors
- `for...of` loops preferred over `.forEach()`

### Functions
- Regular function declarations for top-level functions
- Arrow functions for callbacks and inline usage
- Descriptive function names: `validateFrontmatter()`, `parseYamlLite()`, `generateEntryPoint()`

### Error Handling
- Try/catch around file operations
- Meaningful error messages with file paths
- Non-zero exit codes on validation failures

### Formatting
- 2-space indentation (consistent with `.vscode/` settings)
- Single quotes for strings
- Semicolons at end of statements
- Trailing commas in multi-line arrays/objects

## Markdown Style

### Agent Files (`agents/*.md`)
```markdown
---
(YAML frontmatter)
---

# {emoji} {Agent Name}

| Attribute | Value |
|-----------|-------|
| **ID** | `agent:{name}` |
| **Role** | {role} |
...

> **CORE DIRECTIVE**: {one-sentence mission}

## {Section Headers}
...
```

### Command Files (`commands/*.md`)
- Router files: detect variant, describe routing logic
- Variant files: define phases with agent assignments and exit criteria

### Rule Files (`rules/*.md`)
- Protocol-style with sections, numbered rules, and tables
- Word budget enforced: RUNTIME.md ≤ 3200 words

### General Markdown Conventions
- ATX headings (`#`, `##`, `###`) — no setext underlines
- One blank line between sections
- Tables for structured data (not bullet lists of key:value pairs)
- Inline code backticks for identifiers: `` `agent-name` ``, `` `field-name` ``
- Emoji prefixes on H1 for agents: 🔧, 🎯, 🔍, etc.
- Bold for emphasis, not ALL CAPS (except for CRITICAL/MANDATORY)

## YAML Style

### Frontmatter (in `.md` files)
```yaml
---
schema-version: "1.0"
name: agent-name
description: "Brief description"
profile: "domain:category"
handoffs: [agent-1, agent-2]
category: execution
personality:
  tone: technical
  verbosity: concise
---
```

### Skill Registries (`matrix-skills/*.yaml`)
- 2-space indentation
- Quoted strings for values containing special characters
- Array syntax: inline `[item1, item2]` for short lists, block for longer lists
- Comments with `#` for section headers

### Conventions
- Strings containing colons are quoted: `"backend:execution"`
- Arrays with few items use inline format: `[tester, reviewer]`
- Nested objects use 2-space block indentation
- File-level metadata fields (`version`, `domain`) before content fields

## JSON Style

- 2-space indentation
- Double quotes for all keys and string values
- Trailing commas NOT used (standard JSON)
- Files: `package.json`, `platforms.json`, `.releaserc.json`, `global-patterns.json`

---

## Shell Script Style

### Husky Hooks (`.husky/`)
- Shebang: `#!/usr/bin/env sh`
- Simple one-liner commands
- `npx` for running project scripts in hooks

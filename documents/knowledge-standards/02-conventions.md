## Naming Conventions

### Files and Directories

| Entity | Pattern | Examples |
|--------|---------|---------|
| Agent files | `{kebab-case}.md` | `backend-engineer.md`, `tech-lead.md` |
| Command routers | `{kebab-case}.md` | `cook.md`, `fix.md` |
| Command variants | `{variant}.md` in subdir | `cook/fast.md`, `cook/team.md` |
| Rule files | `{UPPER-KEBAB-CASE}.md` | `RUNTIME.md`, `EVALUATION.md` |
| Skill registries | `{kebab-case}.yaml` | `backend.yaml`, `ai-ml.yaml` |
| Script files | `{kebab-case}.js` | `lint-agents.js`, `simulate.js` |
| Team directories | `{kebab-case}-team/` | `backend-team/`, `frontend-team/` |
| Platform entries | `{UPPER}.md` | `COPILOT.md`, `CLAUDE.md` |
| A2A cards | `{kebab-case}.json` | `backend-engineer.json` |

### Special Prefixes

| Prefix | Meaning | Examples |
|--------|---------|---------|
| `_` | Index/dynamic/meta file | `_index.yaml`, `_dynamic.yaml` |
| `00-` | Index file in knowledge folder | `00-index.md` |
| `generate-` | Generator script | `generate-entry-points.js` |
| `lint-` | Validation script | `lint-agents.js`, `lint-entry-points.js` |

### Identifiers

| Context | Convention | Examples |
|---------|-----------|---------|
| Agent names | kebab-case | `backend-engineer`, `tech-lead` |
| Agent IDs | `agent:{name}` | `agent:backend-engineer` |
| Agent profiles | `{domain}:{category}` | `backend:execution` |
| Command names | lowercase | `cook`, `fix`, `test` |
| Variants | lowercase | `fast`, `hard`, `team` |
| Rule IDs | `R{NNN}` | `R001`, `R300` |
| Categories | lowercase | `execution`, `validation` |

## File Organization

### Top-Level Structure Pattern
```
project-root/
├── agents/          # Entity definitions (static)
├── commands/        # Workflow definitions (static)
├── rules/           # Protocol rules (static)
├── skills/          # Library skills (static)
├── matrix-skills/   # Skill registries (static + dynamic)
├── topologies/      # Coordination patterns (static)
├── guardrails/      # Safety constraints (static)
├── personas/        # Communication profiles (static)
├── schemas/         # Schema definitions (static)
├── cli/             # Executable tooling (code)
├── scripts/         # DevOps tooling (code)
├── web/             # Documentation site (code)
├── a2a-cards/       # Generated artifacts
├── docs/            # Project documentation
└── documents/       # Generated knowledge (by /docs command)
```

### Convention: Content vs Code
- **Content directories** (agents, commands, rules, skills, etc.): Markdown/YAML files that the AI model reads
- **Code directories** (cli, scripts, web): JavaScript/TypeScript files that developers/CI run
- **Generated directories** (a2a-cards, documents): Output from scripts or workflows

### Convention: Router + Variant Pattern
```
commands/
├── cook.md           # Router file — detects variant
└── cook/
    ├── fast.md       # Fast variant workflow
    ├── hard.md       # Hard variant (default)
    └── team.md       # Team variant
```
This pattern applies to all commands that support multiple execution modes.

## Agent Conventions

| Convention | Rule |
|-----------|------|
| One agent per file | Each `.md` in `agents/` is exactly one agent |
| Filename = agent name | `backend-engineer.md` → `name: backend-engineer` |
| Frontmatter first | YAML frontmatter always at top of file |
| H1 with emoji | `# 🔧 Backend Engineer` |
| Attribute table | Standard table with ID, Role, Profile, Reports To, Consults, Confidence |
| Core Directive | Blockquote with `> **CORE DIRECTIVE**: ...` |
| Handoffs must be bidirectional | If A hands off to B, B should list A too (validated by simulate.js) |
| Confidence threshold | Agents declare a confidence % and must escalate when below |

## Command Conventions

| Convention | Rule |
|-----------|------|
| Router in root | `commands/{cmd}.md` — variant detection logic |
| Variants in subdirectory | `commands/{cmd}/{variant}.md` |
| Three standard modes | `:fast`, `:hard` (default), `:team` |
| Phases numbered sequentially | Phase 1, Phase 2, Phase 3... |
| One primary agent per phase | Each phase names exactly one agent |
| Exit criteria explicit | Checkable conditions before proceeding |

## Skill Conventions

| Convention | Rule |
|-----------|------|
| Index file required | `_index.yaml` lists all domains and counts |
| Domain files match index | `backend.yaml` for backend domain |
| Skills have keywords | Enable profile-to-skill matching |
| Library skills have SKILL.md | Deep definitions in `skills/{name}/SKILL.md` |
| Dynamic skills separate | `_dynamic.yaml` for community extensions |

## Schema Versioning

| Convention | Rule |
|-----------|------|
| Schema version in frontmatter | `schema-version: "1.0"` |
| Breaking changes bump version | New required fields → schema version bump |
| Backward compatibility | Newer schemas should handle older versions gracefully |
| Migration scripts | `scripts/migrate-schema.js` for schema transitions |

## Documentation Conventions

| Convention | Rule |
|-----------|------|
| `README.md` per module | Major directories have README files |
| Evidence-backed claims | Documentation references specific source files |
| English for files in `reports/` and `documents/` | Generated documentation always in English |
| Responses in user's language | AI responses match user's language |
| No placeholders | All generated content must be evidence-backed, not templated |

## Branching Strategy

| Branch | Purpose | Protection |
|--------|---------|------------|
| `main` | Production branch, release source | CI must pass, conventional commits |
| Feature branches | Development work | PRs into main |

**Pattern**: Feature branch → PR → CI checks → merge to `main` → semantic-release.

## Commit Message Format

Enforced by `.husky/commit-msg` hook:

```
type(scope): description
```

**Valid types**:

| Type | Semantic Release | Description |
|------|-----------------|-------------|
| `feat` | Minor version | New feature |
| `fix` | Patch version | Bug fix |
| `docs` | No release | Documentation changes |
| `style` | No release | Formatting, whitespace |
| `refactor` | Patch version | Code restructuring |
| `perf` | Patch version | Performance improvement |
| `test` | No release | Test changes |
| `build` | No release | Build system changes |
| `ci` | No release | CI configuration changes |
| `chore` | No release | Maintenance tasks |
| `revert` | No release | Revert a previous commit |

**Breaking changes**: Add `!` after type or include `BREAKING CHANGE:` in commit body → Major version.

**Regex enforced**: `^(feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert)(\(.+\))?: .{1,}`

**Examples**:
```
feat(agents): add security-engineer agent
fix(cli): handle missing platform directory
docs(readme): update installation steps
refactor(scripts): simplify lint-agents validation
chore(release): 2.0.0 [skip ci]
```

## Pre-Commit Validation

`.husky/pre-commit` runs `npm run ci:local` which executes:

| Step | Script | Purpose |
|------|--------|---------|
| 1 | `npm run lint:agents` | Schema validation (R001–R302) |
| 2 | `npm run simulate` | Handoff integrity, skill references |
| 3 | `npm run validate:output` | Deliverable schema validation |
| 4 | `npm run wordcount` | RUNTIME.md ≤ 3200 words |

**All must pass** before the commit is accepted. No `--no-verify` bypass in normal workflow.

## Pull Request Process

From `CONTRIBUTING.md`:

1. **Fork** the repository (external contributors) or create a branch (maintainers)
2. **Implement** changes following coding standards
3. **Validate locally**: `npm run ci:local` must pass
4. **Commit** with conventional commit format
5. **Push** and create PR targeting `main`
6. **CI runs** automatically (GitHub Actions)
7. **Review** by maintainer
8. **Merge** when CI passes and review approved

**PR Expectations**:
- Clear description of what changed and why
- All CI checks green
- No breaking changes without `BREAKING CHANGE:` notation
- Agent changes must pass `lint:agents` validation
- New agents/commands must follow established patterns

## Release Workflow

Fully automated via `semantic-release`:

```
Merge to main
    │
    ▼
GitHub Actions triggers
    │
    ▼
semantic-release analyzes commits since last release
    │
    ├─ feat commits → minor version bump
    ├─ fix/perf/refactor → patch version bump
    ├─ BREAKING CHANGE → major version bump
    ├─ docs/style/test/ci → no release
    │
    ▼
If release needed:
    ├─ Update CHANGELOG.md
    ├─ Bump version in package.json
    ├─ Git commit: "chore(release): X.Y.Z [skip ci]"
    ├─ Git tag: vX.Y.Z
    ├─ Publish to npm
    └─ Create GitHub Release with release notes
```

## CI Pipeline

`.github/workflows/ci.yml`:

| Step | Action | Failure = |
|------|--------|-----------|
| Checkout | `actions/checkout@v4` | — |
| Setup Node | Node.js 18 and 20 matrix | — |
| Install | `npm ci` | Dependency issues |
| Security | `npm audit --audit-level=moderate` | Known vulnerabilities |
| Lint | `npm run lint:agents` | Schema violations |
| Simulate | `npm run simulate` | Handoff/skill errors |
| Wordcount | `npm run wordcount` | RUNTIME.md over budget |
| Validate | `npm run validate:output` | Deliverable format errors |

**Triggers**: Push to `main`, pull requests to `main`.

**Matrix**: Node.js 18, 20 — must pass on both.

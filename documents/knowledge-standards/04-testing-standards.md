## Testing Philosophy

Agent Assistant is a document-driven framework where most "code" is Markdown and YAML definitions read at runtime by AI models. The testing strategy reflects this:

| Layer | What's Tested | Tool |
|-------|---------------|------|
| Schema compliance | Agent frontmatter, skill registries | `lint-agents.js` |
| Structural integrity | Handoff graphs, skill references, missing files | `simulate.js` |
| Word budgets | RUNTIME.md stays within token limits | `wordcount` script |
| Deliverable format | Output schema validation | `validate:output` |
| CLI functionality | Install script correctness | Node.js test runner |
| Web UI | React component/page behavior | Vitest |

**Key insight**: Traditional unit/integration testing applies only to `cli/` and `web/`. The majority of validation is **static analysis of Markdown/YAML** via custom scripts.

## Validation Scripts

### `lint-agents.js` — Schema Validation

Validates all agent files against the frontmatter schema:

| Rule ID | What it checks |
|---------|----------------|
| R001 | `schema-version` field exists and is `"1.0"` |
| R100 | `name` field exists and is kebab-case |
| R101 | `description` field is a non-empty string |
| R102 | `profile` field matches `domain:category` pattern |
| R200 | `handoffs` field is a valid array of known agent names |
| R201 | Bidirectional handoff consistency |
| R300 | `category` field is one of: meta, execution, investigation, validation, research, support |
| R301 | `personality.tone` is a valid value |
| R302 | `personality.verbosity` is a valid value |

**Exit code**: 0 if all pass, 1 if any violations.

### `simulate.js` — Structural Integrity

Performs static analysis without running AI:

| Check | Description |
|-------|-------------|
| Handoff graph | All referenced agents exist, no dangling references |
| Skill references | Skills referenced in agent files exist in registries |
| Command coverage | All commands have router files |
| File existence | Cross-references between files are valid |

### `wordcount` — Budget Enforcement

| File | Budget |
|------|--------|
| `rules/RUNTIME.md` | ≤ 3200 words |

Ensures the critical RUNTIME.md file stays within token-budgeted limits for AI model consumption.

## CI Test Pipeline

The CI pipeline runs tests in this exact order:

```
npm audit --audit-level=moderate    # Security: no known vulnerabilities
        │
        ▼
npm run lint:agents                 # Schema: all agents valid
        │
        ▼
npm run simulate                    # Integrity: handoffs + references
        │
        ▼
npm run wordcount                   # Budget: RUNTIME.md ≤ 3200 words
        │
        ▼
npm run validate:output             # Format: deliverable schemas
```

**All steps must pass.** Pipeline runs on Node.js 18 and 20 matrix.

**Local equivalent**: `npm run ci:local` (runs same steps, enforced by pre-commit hook).

## Test File Conventions

### Core Tests
- Location: Same directory as source file
- Naming: `{source}.test.js` (e.g., `install.test.js`)
- Runner: `node --test`
- Style: Node.js built-in `test()` and `assert` module
- Pattern:
```javascript
import { test } from 'node:test';
import assert from 'node:assert';

test('description of behavior', () => {
  // Arrange, Act, Assert
});
```

### Web Tests
- Location: `web/src/` alongside components
- Naming: `*.test.ts` or `*.test.tsx`
- Runner: Vitest via `npm run test`
- Config: `web/vitest.config.ts`

## What Gets Tested

### Must Have (Enforced by CI)

| Area | Validation | Blocking |
|------|-----------|----------|
| Agent frontmatter | `lint-agents.js` | Yes |
| Handoff integrity | `simulate.js` | Yes |
| Skill references | `simulate.js` | Yes |
| RUNTIME.md word count | `wordcount` | Yes |
| npm dependencies | `npm audit` | Yes |
| Deliverable format | `validate:output` | Yes |

### Should Have (Local Development)

| Area | Tool | Notes |
|------|------|-------|
| CLI install flow | `node --test cli/install.test.js` | Run manually |
| New agent files | `npm run lint:agents` | Catches schema issues early |
| Cross-references | `npm run simulate` | Validates before commit |

### Web-Specific

| Area | Tool | Notes |
|------|------|-------|
| Component rendering | Vitest + Testing Library | `web/` subproject |
| Build verification | `npm run build` in `web/` | Vite build succeeds |

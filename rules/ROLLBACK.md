# ROLLBACK — Pre-Workflow State Restoration

> **Loaded by**: §LOAD ON DEMAND when rollback needed
> **Version**: 1.0

---

## Snapshot Capture (Automatic)

At workflow start:

1. **IF git repo detected**:
   a. Record current branch + commit hash
   b. `git stash push -m "agent-assistant-snapshot-{timestamp}"` (named ref for safe retrieval)
   c. Record stash ref index + message in checkpoint metadata

2. **ELSE (non-git fallback)**:
   a. Scan modified file paths from workflow definition
   b. Record file paths + modification timestamps + SHA-256 hashes
   c. Store metadata in `.agent-assistant/rollback-snapshot.json`

---

## Rollback Execution

On `npm run rollback` command or failure-triggered rollback:

1. **Confirmation prompt**: "Rollback will undo all changes from {workflow}. Continue? [y/N]"
   - `--force` skips interactive confirmation ONLY (audit log still fires)

2. **IF git mode**:
   a. `git checkout -- .` (restore tracked files)
   b. Remove untracked files generated by workflow (from checkpoint metadata)
   c. Locate correct stash by saved message: `git stash list | grep "agent-assistant-snapshot-{timestamp}"`
   d. `git stash apply stash@{N}` using matched index (NOT blind `pop`)
   e. If apply conflicts: warn user, write conflict list to rollback log, do NOT auto-resolve

3. **ELSE (non-git mode)**:
   a. Warn: "Non-git rollback is best-effort. Some changes may not be fully reversible."
   b. Delete generated files (from checkpoint metadata)
   c. Warn user about modified files that can't be auto-restored

---

## Rollback Log

Record in `.agent-assistant/rollback-log.json`:

```json
{
  "entries": [
    {
      "timestamp": "ISO-8601",
      "workflow_id": "string",
      "mode": "git|non-git",
      "files_restored": ["path1", "path2"],
      "files_deleted": ["path3"],
      "conflicts": [],
      "status": "success|partial|failed"
    }
  ]
}
```

---

## Integration with Durable Execution (16.3)

- Pre-workflow snapshot = "Phase -1 checkpoint"
- Rollback from any checkpoint: restore to that checkpoint's state
- Checkpoint chain: snapshot → phase0 → phase1 → ... → phaseN

---

## Constraints

- Rollback does NOT undo external side effects (API calls, database changes)
- Rollback metadata ≤ 50KB (warn if exceeded)
- Stale snapshot cleanup: performed on each `rollback.js` invocation (snapshots >24h are listed for cleanup with user confirmation)

---

## Usage

```bash
npm run rollback                    # interactive rollback
npm run rollback -- --force         # skip confirmation (audit log still fires)
npm run rollback -- --workflow-id X # rollback specific workflow
```
